## 0. 포지셔닝 — "AI 페르소나가 당신의 고객을 먼저 찾아준다"

### 0.1 정체성

41R은 분석 도구가 아니라 **AI 페르소나 기반 마켓핏·고객층 발견
엔진**이다. 한 줄 정의:

> **"런칭 전에, 트래픽 없이 — AI 페르소나 패널이 당신의 제품에
> 반응해서 누가 진짜 고객인지(고객층), 얼마나 맞는지(마켓핏),
> 어디서 이탈하는지(병목)를 알려준다. 실데이터가 쌓일수록
> 페르소나는 더 정확해진다."**

분석 콘솔·트래킹 SDK·설문은 모두 이 엔진의 **입력과 검증 장치**다.
v0.4까지의 문서가 "콘솔(그릇)"을 중심에 뒀다면, v0.5는 "페르소나
(내용물)"를 중심에 놓고 그릇을 재배치한다. 헤드라인 산출물도
바뀐다: 점수가 아니라 **"발견된 고객층"** — "당신의 베스트 핏은
detail_oriented 디자이너 코호트(fit 72), 최악은 …" (Mode A
Discovery가 문자 그대로 이 기능이다 — 이미 만들어져 있고, 전면에
세우지 않았을 뿐).

### 0.2 데이터 플라이휠 (제품의 구조적 해자)

```
① 파운더가 스캔 → AI 페르소나 패널이 fit/고객층/병목 예측
      ↓ (설문 링크 배포 + SDK 설치)
② 휴먼 설문 + 실측 행동 데이터 유입
      ↓
③ 페르소나 칼리브레이션 — 예측 vs 실측 괴리를 측정·교정
   (calibration_records + INTENT_ACTION per-category + by_cohort 검증)
      ↓
④ 테스터 풀 성장 → 실인물 기반 페르소나 생성
   (절차적 합성 페르소나의 다양성 한계를 실데이터가 돌파 — 기존
    Known Limitations §8의 해소 경로이자 41R Persona Market 원래 비전)
      ↓
⑤ 더 정확한 고객층 발견 → 더 많은 파운더 → ①로
```

이 플라이휠 관점에서 각 기능의 존재 이유가 재정의된다:

| 기능 | v0.4까지의 프레임 | v0.5 프레임 |
|---|---|---|
| 스캔 | 상품 (리포트 판매) | 상품 + 페르소나 출력 단면 |
| 설문 | 비교 기능 ("AI vs Human") | **칼리브레이션 연료** — 응답 1건 = 페르소나 정확도 데이터 1건 |
| SDK 트래킹 | GA 대체 분석 | **예측 검증 장치** — visitor-weighted 예측을 실측과 대조, 괴리가 칼리브레이션 입력 |
| 테스터 | 설문 응답자 | **페르소나의 원천** — 장기적으로 실인물 페르소나 공급자 |
| 결합 뷰 | 차별화 카드 | 플라이휠 ③이 사용자 눈에 보이는 형태 |

### 0.3 경쟁 지형 — 누구와 싸우고 어디로 피하나

| 대안 | 그들이 주는 것 | 못 주는 것 (41R의 자리) |
|---|---|---|
| **Wynter** (가장 근접) | 실인물 B2B 패널의 카피/메시지 테스트 | 패널 모집 대기 + 고가($) + 1회성. 41R: 즉시·반복·저가, 코호트 8종 동시 |
| **Maze / UserTesting** | 리얼 유저 테스트 세션 | 같은 한계 + 셋업 비용. 41R: URL만으로 3분 |
| **GA4 / Mixpanel** | 트래픽 발생 후의 행동 사실 | **트래픽 0에선 무력** + "누가 와야 하는지" 답 못 함 |
| **Hotjar / MS Clarity** | 세션 리플레이·히트맵 (Clarity 무료) | 마찬가지로 사후적. 단 **무료라서 TRACKED 티어 단독으론 경쟁 불가** — 트래킹은 상품이 아니라 칼리브레이션 장치라는 포지션이 여기서도 강제됨 |
| ChatGPT에 "내 사이트 평가해줘" | 1인분 LLM 의견, 공짜 | 단일 시점·단일 페르소나·재현 불가. 41R: 구조화된 N-페르소나 패널 + 수치 계약 + 칼리브레이션 이력 |

피해야 할 싸움: 트래킹 기능으로 Clarity와, 패널 깊이로 UserTesting과
정면 대결. 이길 싸움: **"런칭 전 + 즉시 + 교정되는 예측"**의 3박자는
위 누구도 못 한다.

### 0.4 정직성 계약 (포지셔닝이 강해질수록 더 load-bearing)

"AI가 고객을 찾아준다"는 약속은 과신을 팔기 쉽다. 기존 계약을
약화 없이 승계한다: persona-conditional 경고 배너, visitor 뷰
"experimental — directional only", BIGGEST LEAK(병목 진단) 프레이밍,
synth 마커, by_cohort 정확도 공개 ("novice 코호트 |Δ|=0.25, advanced
|Δ|=1.69 — 페르소나 정확도는 코호트별로 다르며 그 자체가 인사이트").
**칼리브레이션 이력을 숨기지 않고 파는 것**이 이 포지션의 신뢰
전략이다 — "우리 예측은 이만큼 맞고 이만큼 틀리며, 점점 나아진다"를
보여줄 수 있는 경쟁자는 없다.

## 1. 핵심 모델 — 워크스페이스와 2-티어 (확정 유지)

### 1.1 사이트 등록 = 워크스페이스 (소유 아님)

- 등록 단위 `(user, site URL)`. **같은 URL을 여러 사용자가 각자 등록
  가능** — 워크스페이스 간 완전 격리, 서로의 존재도 안 보임.
- 모이는 데이터는 전부 등록자 본인 것 (본인 스캔·본인 설문·본인 site
  key의 이벤트) — **도메인 검증 영구 제외 확정**. 소유 증명은 SDK
  설치 가능 여부가 자연스럽게 한다 (GA 속성 모델).

### 1.2 LITE / TRACKED — 티어는 창발

| | **LITE (외부 분석)** | **TRACKED (SDK 설치)** |
|---|---|---|
| 조건 | URL 등록만 | t.js 첫 비콘 수신 시 자동 |
| 대상 | 경쟁사·관심 사이트 포함 누구의 사이트든 | 코드 넣을 수 있는 사이트 (자연 게이트) |
| 가치 | 페르소나 패널의 고객층 발견 + 설문 칼리브레이션 | + **예측 vs 실측 검증** (결합 뷰) — "내 예측이 맞는지 확인" |

TRACKED의 셀링 포인트가 재정의됨: "GA 대신 쓰세요"가 아니라
**"페르소나가 예측한 고객층·퍼널이 실제와 맞는지 검증하고, 당신
사이트에 맞게 교정받으세요"**. (Clarity가 무료인 세상에서 트래킹
자체는 팔 물건이 아니다 — §0.3.)

### 1.3 사용 시나리오

1. **프리런치 파운더** (핵심 ICP): 등록 → 스캔 "내 고객층은 누구?"
   → 설문으로 검증 → 런칭 후 SDK → 예측 vs 실측.
2. **경쟁사 벤치마크**: 경쟁사 URL 등록(영구 LITE) → "쟤네는 어떤
   코호트에 먹히나" — 고객층 비교. *(나란히 비교 화면 v2)*
3. **파트너(글밭형)**: TRACKED + 설문 핸드오프 + 프로필 스트림 =
   플라이휠 ②③④를 한 파트너 안에서 전부 도는 풀 시나리오.

## 4. 크레딧 모델 (v0.4 확정 + 응답 가격 이원화)

**가입 시 $30 크레딧** (확정). 레저는 `credit_transactions`
append-only (§9.1b), 포인트와 별개 통화, 만료 90일 제안, v1 빌링
없음 (소진 시 수동 지급/대기 — 가격표·레저는 실가동하므로 충전
빌링은 결제 수단만 추가).

### 4.1 가격표 v0.5 (휴먼 응답 모순 해소)

| 행위 | 가격 | 근거 |
|---|---|---|
| Mode A 스캔 | **$2** (확정 — 활성화 우선으로 인하) | 실원가 ~$0.15의 13× — 마진 충분, 횟수를 늘려 습관 형성 |
| Mode B 스캔 | **$1** (확정) | 〃 (~$0.07) |
| **설문 — 자체 배포** (파운더가 링크 직접 뿌림) | **무료** | 응답 1건 = 칼리브레이션 데이터 1건 — **우리가 받는 가치가 있어 보상(100pt)도 41R이 부담** (데이터 취득 비용, CAC 아님). 스캔당 30명 보상 캡 유지 |
| **설문 — 41R 풀 모집** (우리가 테스터 매칭) | **$1/건** | 본 상품 — 보상 재원 + 마진. **테스터 풀 임계치(코호트당 ~50명) 전까지 판매 보류** — v1 메뉴에 "준비 중" 노출만 (§13) |
| 행동 트래킹 | 무료 (10만 ev/월 soft cap) | 칼리브레이션 장치 + Clarity 무료 대항 (§0.3) |
| 워크스페이스 / 리포트 링크 | 무료 | PLG 퍼널 / 바이럴 |

- v0.4의 모순("자기가 뿌린 응답에 왜 $1?")은 이원화로 해소. 자체
  배포가 무료여도 손해가 아니다 — **응답이 페르소나 엔진의 연료**
  라는 재포지셔닝(§0.2)이 무료의 명분이자 보상 부담의 명분.
- $30 = **Mode A 15회** (또는 A 10 + B 10 혼합) — 인하 확정의 의도:
  가치 anchoring보다 **활성화(반복 스캔 습관)** 우선. 자체 배포
  설문이 무료라 보너스 전액이 스캔(=페르소나 패널 가동)에 쓰인다.
- 실원가 노출: $30 소진 시 LLM ~$2.3 + 자체 배포 보상 부채 (캡
  30명×스캔). 마크업 구조 덕에 보너스는 여전히 싸게 준다.

### 4.2 어뷰즈 (v0.4 유지 + 보강)

가입 보너스 파밍(**확정**: 검증 신원(이메일/Google/소셜) $30,
지갑-only $5 — 이메일 연결 시 차액 지급) / 스캔 폭주
(크레딧+rate limit) / **설문 자작** — 자체 배포가 무료가 되면서
자작의 경제성이 되살아나므로 보강: 스캔당 보상 캡 30 + 계정당 일일
적립 상한 + 동일 결제지문/IP 클러스터 휴리스틱은 v2, v1은 캡 2종으로
부채 상한 고정. 가짜 비콘은 v1 수용 (GA 동일 노출, 월 상한으로 폭주만
차단).

### 4.3 포인트 정책 (유지)

환산율 미정 유지. 풀 모집 가격 $1이 환산율의 구조적 상한 (보상 ≤ $1
− 마진). 확정 시점 = 충전 빌링 개시와 동시. UI 카피 "출금/전환 정책
준비 중".

## 5. 북극성 지표 · 계측 · Dogfooding (신규)

### 5.1 북극성 (확정)

**주간 칼리브레이션 활성 워크스페이스** — 그 주에 "스캔 1회 이상 AND
(설문 응답 ≥1 OR 비콘 수신)"인 워크스페이스 수. 단순 WAU가 아니라
이걸 고르는 이유: 스캔만 도는 건 일회성 도구 사용이고, 설문/실측이
함께 돌아야 플라이휠 ②③이 도는 것 — **제품 성공과 페르소나 엔진
개선이 같은 지표로 묶인다.**

### 5.2 퍼널 계측 (우리 자신의)

```
visit → signup → first_scan → workspace_created
  → first_survey_response → sdk_first_beacon → (return week 2)
```

- 분석 제품이 자기 퍼널을 못 재는 건 자기모순. **41R 웹앱에 41R
  t.js를 단다 (dogfooding)** — 별도 계측 인프라 없이 자기 제품으로
  자기 깔때기를 본다. 시스템 이벤트(signup, scan 등)는 서버에서 동일
  파이프라인에 흘림.
- 부수 효과: 운영자가 매일 보는 첫 TRACKED 워크스페이스가 생긴다 —
  분석 탭의 첫 실사용자가 우리 자신 (UX 결함을 우리가 먼저 맞음).

### 5.3 칼리브레이션 지표 (엔진의 정확도 — 제품 지표와 분리)

by_cohort |Δ| (페르소나 vs 휴먼, 차원별) / 예측-실측 괴리 (visitor
AARRR vs 실측 퍼널, TRACKED 한정) / GA4 reference n (현 1 → 목표 5+
per category). 분기마다 `/validator/calibration`(operator)에 갱신 —
**이 숫자의 개선 추이 자체가 투자/영업 자료** (§0.4 — 정직성을 파는
전략의 백데이터).

  먼저 보기" — 기존 uniswap 스캔 재활용, 비용 0).

### 8.1 `site_workspaces`

### 8.2 `credit_transactions`

```
id · user_id · amount_cents(+지급/−차감) · reason(signup_bonus|scan_mode_a|

```
append-only (point_transactions 계약 복제). 잔액=SUM. 스캔 선차감 +
실패 refund 행. 지급은 users 생성 시 1회 idempotent.

### 8.3 연결 규칙 / 글밭 마이그레이션 / API (v0.4 그대로)

- 스캔 `workspace_id` nullable FK (콘솔 발 명시 연결, 과거분 host
  backfill + Unassigned 수동 연결, 익명 null 허용).
- 행동 이벤트 site_key → workspace 해석. 파트너 프로필/포인트
  source → workspace 일반화.
- 글밭: env 키 값 그대로 1행 시드(무중단) · `requireGeulbatKey` →
  `requireSiteSecret` · geulbat 경로 alias 보존 · `claimPartnerRows`
  일반화(non-fatal + already-submitted 가드 유지) · prod 스키마 변경
  idempotent SQL 수동 적용 (drizzle journal 공백).
- API: `/api/console/sites` CRUD + rotate-key + analytics + link-scan,
  `/api/me/credits`. 전부 requirePrivyAuth + owner WHERE 격리.
  human-aggregate owner 검사, calibration operator 게이트.
- 미들웨어: rate limit (scan 5/min·IP, 20/h·user, mutation 30/min) +
  credit debit + 보상 캡. 디자인은 기존 토큰만.
